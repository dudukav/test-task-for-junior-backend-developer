# Предположения

1. Замена ID int64 на uuid. Int64 можно использовать в небольшом проекте, в целом, можно было бы оставить, но uuid лучше в случае, если сервис будет масштабироваться, будут появляться новые микросервиса, плюс ко всему, uuid спасает от коллизий. К сожалению, он занимает больше места, но при это с точки зрения масштабирования подходит больше

2. Расписание создается по щаблону не сразу на все последующие дни, а с помощью планировщика. Если сразу создать все расписание, можно перегрузить бд и в целом все операции станут дороже, так как иногда требуется изменить шаблон, тогда нам надо будет идти по всем возмонжным созданным задачам и менять их, что сильно нагружает сервис. Мое решение предполагает создание задач раз в сутки. Планировщик проверяет активна ли задача, не отменили ли ее, и создает следующую запланированную задачу по шаблону

3. С точки зрения архитектуры конфиг я вынесла в отдельный файл, так как main отвечает за запуск сервиса. В идеальном варианте можно было бы сделать сборщик сервиса, а в main только вызывать его. Это правильно с точки зрения чистой архитектуры, так как main не должен в целом знать о внутренних сущностях

4. Добавила линтер для проверки на чистоту кода

# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.

## Swagger

Swagger UI:

```text
http://localhost:8080/swagger/
```

OpenAPI JSON:

```text
http://localhost:8080/swagger/openapi.json
```

## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`
